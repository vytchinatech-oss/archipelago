# Архипелаг — протокол чата

Игра «Архипелаг»: градостроительный и экономический симулятор. Владелец — Владислав, общение по-русски, простым языком.

- Репозиторий: vytchinatech-oss/archipelago, ветка main.
- Опубликованная игра: ссылка в docs/STATUS.md. Обновлять именно этот артефакт (передавать его url при публикации), новый не создавать.

## Какую модель советовать

В начале чата и в конце, для следующего чата, называй модель под задачу. Сам переключить модель чата ты не можешь: это делает владелец в списке моделей.

- **Claude Fable** — самое сложное: большая новая система, которая затрагивает много правил, запутанная ошибка, которую не удалось найти с первого раза.
- **Claude Opus** — обычная новая механика, заметная правка кода, режим «Дизайн», ошибка.
- **Claude Sonnet** — плейтест и правка баланса, небольшие правки кода и интерфейса.
- **Claude Haiku** — режим «Итог», правка текста или одной цифры.

Если у модели в списке вышла новая версия, советуй её. Если текущая модель слабее нужной и задача большая — предложи переключиться и подожди ответа. Если модель подходит или сильнее нужной — скажи об этом коротко и работай дальше. Субагентов запускай без параметра model. Если агента проекта (`qa`, `controller` …) нет в списке сессии — запусти общего агента и первой строкой задания дай ему прочитать свою инструкцию `.claude/agents/<агент>.md`.

## Определи режим по сообщению

Если режим неясен — один короткий вопрос, какой из пяти.

1. **Задача** — новая механика или заметная правка кода.
2. **Дизайн** — обсуждение без кода.
3. **Плейтест** — владелец рассказывает впечатления от игры, правим баланс.
4. **Ошибка** — что-то сломалось.
5. **Итог** — владелец просит подвести итог и закрыть чат.

## Начало (все режимы, кроме «Итог»)

1. Подключи репозиторий (add_repo с доступом push), если его нет в сессии. Если папка уже есть — не клонируй поверх; `git pull` — после сверки (шаг 3).
2. Прочитай CLAUDE.md, docs/STATUS.md и docs/OFFICE.md (разделы 1, 4а, 5, 5а — офис 2.0). Для задачи и ошибки — ещё docs/ARCHITECTURE.md и нужные разделы docs/DESIGN.md.
3. **Ворота 0 — сверка состояния одной командой** (OFFICE.md, раздел 5а). Узнай версию артефакта: get_artifact по ссылке из STATUS.md, заголовок «Архипелаг X.Y.Z». Затем `npm run check -- --published X.Y.Z`. Скрипт сверяет main, версии (package.json, main, STATUS.md, dist, артефакт), замок, ветки, стопы и дату аудита.
   - Итог «СТОП» (код 2) — расхождение версии или main: работу не начинать, сказать CEO. Если стоп только «в origin/main есть коммиты, которых нет здесь» — прочитай их (`git log HEAD..origin/main`: чьи, что меняют), назови CEO чужие, сделай `git pull --rebase` и повтори сверку.
   - Итог «НАХОДКИ» (код 1) — позвать агента `controller` с выводом скрипта и работать дальше.
   - Итог «СХОДИТСЯ» — дальше.
   Задача из текущего этапа или дизайн следующего? Иначе — во «Входящие» и предложение продюсера. Строки «Урок: …» без решения в docs/LESSONS.md — заместителю или CEO.
4. **Замок** (служебный чат — документы, решения CEO — замок не берёт). Строка «Код» или «Дизайн» в STATUS.md:
   - занята свежим чатом — не начинать, сказать CEO; без коммитов больше 24 часов — позвать `controller`;
   - свободна — впиши «чат и задача, ветка, с какого времени» и закоммить **только этот файл**: `git commit docs/STATUS.md -m "Замок «Код» (этап …): …"`. Не `git commit -a` и не `git add .` — в коммит замка попадёт чужое, например пересобранный dist (урок У20).
   - `git push`, затем `git fetch` и `git show origin/main:docs/STATUS.md | grep -A2 "Замок"`: строка твоя? Если два чата заняли её одновременно, остаётся тот, чей коммит раньше, второй отступает.
5. Одной фразой скажи, что понял и что сделаешь, и какая модель подходит для этой задачи.
6. Если задача большая — предложи разбить и делай только первую часть.

## Режим «Задача»

1. Развилки — сначала агенту `deputy` (заместитель CEO) с вариантами и доводами за каждый. Если механика меняет задумку или заместитель ответил «ВЕРНУТЬ CEO» — вопросы CEO (AskUserQuestion, до 4 за раз) до уверенности ~95%; «ВЕРНУТЬ CEO» останавливает только зависимые задачи. Решения — в docs/DESIGN.md, решения заместителя — в OFFICE.md, разделы 9 и 9а.
2. Проверь конфликты с существующими правилами: найм по приоритету, ореолы, энергия, пошлины, договоры, выборы, министры. Раздел «Аудит» в DESIGN.md.
3. Цифры баланса — в src/data/, логика — в src/sim/, интерфейс — в src/ui/. Новые файлы — в списки build.mjs.
4. Новое правило — новый тест в tests/rules.test.mjs.
5. У каждой новой кнопки есть data-tip, интерфейс проверен на ширине ~390 px.
6. Новое поле состояния S — добавь в newGame/govInit. Если старые сохранения ломаются — подними `SAVE_V` в src/core/constants.js (единственное место номера версии; шаг перевода — в migrateSave) и SAVE_KEY.

## Режим «Дизайн»

Кода не пиши. Дизайн — только для следующего по очереди этапа. Авторы — агенты `game-designer` (смысл и выбор игрока) и `economist` (цифры и связи), `ux` — как объяснить игроку; предлагай механики из лучших стратегий. Развилки — заместителю, что меняет задумку — CEO. Ворота 1 проверяют не авторы: `playtester` (прогон модели) и `tech-director` (выполнимость). Итог — раздел в docs/DESIGN.md со строкой «Ворота 1: …», пункт в «Дальше» в docs/STATUS.md, коммит.

## Режим «Плейтест»

Разбери впечатления на конкретные причины. Правь цифры в src/data/, проверяй долгими прогонами (tests/world.test.mjs) и прогоном стратегий агентом `playtester`; цифры проверяет `economist`. Объясни, что поменял и почему.

## Режим «Ошибка»

Воспроизведи в тесте, почини, оставь тест. Игровой цикл обёрнут в guard() — не убирай.

## Конец (каждый режим, включая «Итог»)

1. `npm test` — всё зелёное. Если менялся интерфейс — один скриншот на ширине 390 px или `python3 tools/browser-smoke.py`.
2. **Ворота 3** по уровню задачи (OFFICE.md, раздел 5): мелкая правка — `qa`; правила, цифры, интерфейс, технология — `qa` и профильные агенты по таблице; закрытие этапа — полный состав. Свою работу не проверяешь. На «нет» — правки и повторная проверка тем же агентом; спорное замечание решает `deputy`.
3. Обнови docs/STATUS.md (Готово / В работе / Дальше / стопы / фраза для следующего чата) и docs/CHANGELOG.md. Новые решения — в docs/DESIGN.md.
4. **Ворота 4:** `npm run check -- --gate 4 --tests` (рабочая копия новее main — ожидаемо). Затем **свежий вызов `controller`, всегда**, с выводом скрипта: сверка рабочей копии; в STATUS.md нет «влито», «опубликовано», «проверено» без источника.
5. `git pull --rebase`, коммит на русском со строками «Ворота 3: …» и «Контролёр: …», пуш в main. Пуш не прошёл — не публиковать.
6. Если менялся код — опубликуй dist/index.html в тот же артефакт по ссылке из STATUS.md, заголовок «Архипелаг <версия>». Последний коммит чата меняет только STATUS.md — строка «Опубликована …» и снятый замок: `git commit docs/STATUS.md -m "Опубликована …, замок снят"`, не `-a`. После пуша и публикации — `npm run check -- --published <версия>`: не должно быть «СТОП»; находки — `controller`.
7. Скопируй изменённые docs/OFFICE.md, docs/STATUS.md, CLAUDE.md, docs/MECHANICS.md в документы проекта claude.ai (claude/…).
8. Ответ владельцу: что сделано (коротко, без технических деталей), что проверить в игре, фраза для следующего чата и какую модель в нём включить.

## Когда предложить новый чат

Чат длинный, решена основная задача, или владелец сменил тему — предложи закончить: выполни «Конец» и дай фразу для нового чата.
