# Архипелаг — правила работы для Claude

Градостроительный и экономический симулятор на островах. Игрок — глава страны: строит города, ведёт экономику и торговлю, ладит с соседями, выигрывает выборы или удерживает трон. Владелец проекта — Владислав; общаемся по-русски, простым языком.

## Офис разработки
Проект ведётся по уставу `docs/OFFICE.md` (редакция 2.0 от 12 ноября 2026): курс, единственная очередь этапов, блоки и подчинение (раздел 4), матрица решений (4а), ворота задачи (5), правда о состоянии и замок (5а), бюджет чата (5б), стратегическая сессия (7а), как команда учится (7б, журнал `docs/LESSONS.md`). Владислав — CEO, последнее слово за ним. Команда не меняет очередь сама: всё, что не из текущего этапа, идёт во «Входящие» или к CEO как предложение продюсера.

Агенты в `.claude/agents/`, у каждого — должностная инструкция по одному шаблону:
- **Решения:** `deputy` (заместитель CEO).
- **Управление:** `producer`.
- **Игра:** `game-designer`, `economist`, `ux` — авторы дизайна следующего этапа и проверяющие.
- **Технологии:** `tech-director`; рабочий чат — ведущий разработчик.
- **Издание:** `publisher`.
- **Контроль** (подчиняется прямо CEO, может остановить работу по фактам): `controller`, `qa`, `playtester`.

Агенты файлов не меняют; записывает ведущий. Кто делает — себя не проверяет.

**Ведущий разработчик (рабочий чат):** проходит ворота 0, 2 и 4, держит замок (контролёр только следит и снимает брошенный), пишет код, тесты и документы, записывает решения и тексты авторов, зовёт проверяющих по таблице ворот 3. Свою работу не проверяет.

**Заместитель CEO** — агент `deputy`. Когда задача ждёт решения CEO (выбор варианта, предложение продюсера, нестыковка У, спорное замечание проверки), сначала спроси заместителя и не останавливайся. Его ответ «ВЕРНУТЬ CEO» — не стоп: записать вопрос в `STATUS.md`, «Ждут ответа CEO», со списком зависимых задач и не брать задач, которые от него зависят; независимые можно. Решения заместителя — в OFFICE.md, разделы 9 (журнал, пометка «заместитель») и 9а (таблица). Полномочия — OFFICE.md, раздел 1.

**Страна — не стоп-сигнал (договорённость с CEO, 11 ноября 2026).** Если площадке, краудфандингу или платёжной системе нужны иностранная компания, резидентство или зарубежный счёт, не пиши «нельзя» и не ставь блок из-за России или Крыма. Ставь задачу: что оформить, в какой стране, сколько стоит и занимает, к какому этапу нужно. CEO может оформить компанию за рубежом. Юридическую проверку делает юрист — это тоже задача в плане.

## Бюджет чата — экономия токенов
Решение CEO 19.11, полный текст — `OFFICE.md`, раздел 5б. **Где правило расходится с остальным текстом — действует оно.**
- Читать оглавление (`grep -n '^#'`), потом только нужный раздел; `STATUS.md` — только «Замок», «Стопы», «В работе», «Входящие», «Дальше», «Ждут ответа CEO»; код — `grep -rn` и одна функция; свой файл после правки не перечитывать; документы проекта claude.ai не читать — правда в репозитории.
- Вывод команд — коротко: `npm test 2>&1 | tail -20`, `git … --stat | head`, из `npm run check` — итог и строки стопов/находок.
- Агенты: ворота 3 и 4 — **один агент на все нужные роли**, с `git diff --stat`, изменёнными кусками и форматом ответа «да/нет, до 15 строк»; повтор — тем же агентом. Лимит: мелкая правка — 1 вызов, задача — 1–2, закрытие этапа — до 3, больше — спросить CEO. `deputy` — только если CEO нет в чате. Ворота 0 без стопа — агентов не звать, находки во «Входящие» `STATUS.md`. Свежий `controller` — только закрытие этапа или находки/стоп `npm run check`.
- `STATUS.md` — до ~80 строк, все удаляемые абзацы — в `CHANGELOG.md`. В проект claude.ai — только `STATUS.md` и файлы, где поменялся смысл, через `project_write` с `local_path`.
- Ход работы не пересказывать, код и diff в чат не печатать, итог CEO — до 10 строк. Одна задача — один чат.
- В последнем коммите к строке «Чат: …; вызовов агентов: N» — «бюджет: в норме | превышен — почему».

## Начало каждого чата
0. Ворота 0 (OFFICE.md, разделы 5 и 5а): **сверка состояния** по списку 5а одной командой `npm run check -- --published X.Y.Z` (версия — заголовок артефакта) — расхождение версии или `main` (статус, `package.json`, опубликованная игра) останавливает работу, сначала сказать CEO; находки без стопа (например, старый аудит) — строкой во «Входящие» `STATUS.md`, агентов не звать (5б), работать дальше. Задача из текущего этапа или дизайн следующего? (служебная — без замка). **Замок** — по ответу строка «Код» или «Дизайн» в `STATUS.md`: свободна → занять отдельным коммитом и проверить после пуша, что она твоя; занята свежим чатом → не начинать, сказать CEO; старше 24 часов → позвать `controller`. Строки «Урок: …» из последнего аудита и прошлого чата без решения в `docs/LESSONS.md` — заместителю или CEO (матрица 4а).
1. Прочитай в `docs/STATUS.md` блоки «Замок», «Стопы», «В работе», «Входящие», «Дальше», «Ждут ответа CEO».
2. Найди через `grep -n '^#'` и прочитай только нужные разделы `docs/DESIGN.md`.
3. Если задача трогает код — нужный раздел `docs/ARCHITECTURE.md`.
4. Одна задача на чат. Если просьба большая, предложи разбить.

## Конец каждого чата
1. `npm test` — все тесты зелёные.
2. Ворота 3: независимая проверка по уровню задачи (OFFICE.md, раздел 5) — все роли одним вызовом агента (раздел 5б), кроме закрытия этапа; агента звать после шага 3, когда `STATUS.md` и `CHANGELOG.md` уже обновлены. На «нет» — вернуться в работу, после правок — повторная проверка тем же агентом (SendMessage). Итог — одной строкой в сообщение коммита.
3. Обнови `docs/STATUS.md`: что сделано, что дальше, стопы. Новые решения — в `docs/DESIGN.md`. Строка в `docs/CHANGELOG.md`. Был промах или повтор замечания (сверь замечания проверки с `docs/LESSONS.md`) — строка в `docs/LESSONS.md` и во что его превратить (тест, пункт в «Уроках» агента, правило; OFFICE.md, раздел 7б). Строки «Урок: …» из проверок этого чата — сразу заместителю (пункт «Уроков») или CEO (устав, «Уроки» заместителя и контролёра).
4. Ворота 4 — `npm run check -- --gate 4 --tests`; при «СХОДИТСЯ» роль `controller` берёт объединённый агент ворот 3, свежий `controller` — только при закрытии этапа или находках скрипта (5б): сверка рабочей копии (старая версия в `origin/main` и в опубликованной игре до пуша — ожидаема), в `STATUS.md` нет «влито», «опубликовано», «проверено» без источника. Его итог — в сообщение коммита.
5. `git pull --rebase`, коммит с понятным сообщением на русском, пуш в `main`. Пуш не прошёл — не публиковать. В последнем коммите чата — строка «Чат: код | дизайн | служебный; вызовов агентов: N (qa 2, controller 1 …); бюджет: в норме | превышен — почему» для счёта цены процесса (OFFICE.md, раздел 7б).
6. Опубликуй `dist/index.html` в артефакт из STATUS.md с заголовком «Архипелаг <версия>». Последний коммит чата: строка «Опубликована …» и **снятый замок** в `STATUS.md`.
7. Скопируй в проект claude.ai `docs/STATUS.md` и те из `docs/OFFICE.md`, `CLAUDE.md`, `docs/MECHANICS.md`, где менялся смысл (`project_write` с `local_path`) (если у чата нет доступа к проекту — назови CEO файлы, он скопирует).
8. Подскажи владельцу, с какой фразы начать следующий чат.

## Как устроен код
- Модули в `src/` — обычные скрипты с общими глобальными именами, без import/export. Порядок подключения задан в `build.mjs` (CORE → DATA → SIM → VIEW). Новый файл добавляй в нужный список там же.
- `src/data/` — только таблицы и цифры баланса. Числа меняются здесь, а не в логике.
- `src/sim/` — логика без DOM. Всё, что меняет правила, должно быть проверяемо в Node.
- `src/render/`, `src/ui/` — только браузер.
- Состояние игры — один объект `S` (см. `sim/economy.js`). Новое поле: добавь в `newGame`/`govInit`, подумай о сохранении (версия `S.v`, ключ `SAVE_KEY` в `ui/app.js`).
- Сборка: `npm run build` → `dist/index.html`, один самодостаточный файл. Его публикуют как артефакт claude.ai.

## Правила изменений
- Каждое новое правило игры — тест в `tests/rules.test.mjs`. Баланс — проверить прогоном `tests/world.test.mjs`.
- Перед изменением механики проверь конфликты с существующими правилами (найм по приоритету, ореолы, энергия, пошлины, договоры, выборы). Список прошлых конфликтов — в `docs/DESIGN.md`, раздел «Аудит».
- Игровой цикл обёрнут в `guard()`: ошибка не должна останавливать игру. Не убирай.
- Интерфейс работает на телефоне: проверяй ширину ~390 px, долгое касание для подсказок, у каждой кнопки `data-tip`.
- Тексты для игрока — по-русски, коротко, без канцелярита. **С этапа 0а все новые тексты — через словарь, не строкой в коде** (решение CEO, выход на мировой рынок).
- **Всё, что может стать дополнением** (OFFICE.md, этап 11), — отдельным модулем со своими таблицами в `src/data/` и правилами в `src/sim/`; игра без модуля работает, проходит тесты и открывает сохранения.
- Перед заметным изменением механики, которое меняет задумку, спроси владельца.

## Команды
- `npm test` — сборка и все тесты (Node 22, `.nvmrc`; отпечатки эталона партий зависят от основной версии Node).
- `npm run build` — только сборка.
- `python3 tools/browser-smoke.py [chrome]` — необязательный стресс-тест в браузере (нужен playwright).
