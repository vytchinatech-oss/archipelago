# Архипелаг — правила работы для Claude

Градостроительный и экономический симулятор на островах. Игрок — глава страны: строит города, ведёт экономику и торговлю, ладит с соседями, выигрывает выборы или удерживает трон. Владелец проекта — Владислав; общаемся по-русски, простым языком.

## Офис разработки
Проект ведётся по уставу `docs/OFFICE.md`: курс, единственная очередь этапов, роли, ворота задачи, правило изменения очереди. Владислав — CEO, последнее слово за ним. Команда не меняет очередь сама: всё, что не из текущего этапа, идёт во «Входящие» или к CEO как предложение продюсера. Независимые проверяющие — агенты в `.claude/agents/` (producer, game-designer, economist, qa, ux).

**Заместитель CEO** — агент `deputy`. Когда задача ждёт решения CEO (выбор варианта, предложение продюсера, нестыковка У, спорное замечание проверки), сначала спроси заместителя и не останавливайся. Его ответ «ВЕРНУТЬ CEO» — остановиться: записать вопрос в `STATUS.md`, «Ждут ответа CEO», и не брать новых задач, которые от него зависят. Решения заместителя — в журнал OFFICE.md, раздел 9, с пометкой «заместитель». Полномочия — OFFICE.md, раздел 1.

## Начало каждого чата
0. Быстрая проверка курса (OFFICE.md, раздел 7) и ворота 0: задача из текущего этапа?
1. Прочитай `docs/STATUS.md` — что сделано и что в работе.
2. Прочитай нужные разделы `docs/DESIGN.md` — механики и принятые решения.
3. Если задача трогает код, посмотри `docs/ARCHITECTURE.md`.
4. Одна задача на чат. Если просьба большая, предложи разбить.

## Конец каждого чата
1. `npm test` — все тесты зелёные.
2. Ворота 3: независимая проверка агентами по таблице в OFFICE.md, раздел 5. На «нет» — вернуться в работу.
3. Опубликуй `dist/index.html` в артефакт из STATUS.md.
4. Обнови `docs/STATUS.md`: что сделано, что дальше. Новые решения — в `docs/DESIGN.md`. Строка в `docs/CHANGELOG.md`.
5. Коммит с понятным сообщением на русском, пуш.
5а. Обнови копии `docs/OFFICE.md`, `docs/STATUS.md`, `CLAUDE.md`, `docs/MECHANICS.md` в проекте claude.ai, если они менялись.
6. Подскажи владельцу, с какой фразы начать следующий чат.

## Как устроен код
- Модули в `src/` — обычные скрипты с общими глобальными именами, без import/export. Порядок подключения задан в `build.mjs` (CORE → DATA → SIM → VIEW). Новый файл добавляй в нужный список там же.
- `src/data/` — только таблицы и цифры баланса. Числа меняются здесь, а не в логике.
- `src/sim/` — логика без DOM. Всё, что меняет правила, должно быть проверяемо в Node.
- `src/render/`, `src/ui/` — только браузер.
- Состояние игры — один объект `S` (см. `sim/economy.js`). Новое поле: добавь в `newGame`/`govInit`, подумай о сохранении (версия `S.v`, ключ `SAVE_KEY` в `ui/app.js`).
- Сборка: `npm run build` → `dist/index.html`, один самодостаточный файл. Его публикуют как артефакт claude.ai.

## Правила изменений
- Каждое новое правило игры — тест в `tests/rules.test.mjs`. Баланс — проверить прогоном `tests/world.test.mjs`.
- Перед изменением механики проверь конфликты с существующими правилами (найм по приоритету, ореолы, энергия, пошлины, договоры, выборы). Список прошлых конфликтов — в `docs/DESIGN.md`, раздел «Аудит».
- Игровой цикл обёрнут в `guard()`: ошибка не должна останавливать игру. Не убирай.
- Интерфейс работает на телефоне: проверяй ширину ~390 px, долгое касание для подсказок, у каждой кнопки `data-tip`.
- Тексты для игрока — по-русски, коротко, без канцелярита. **С этапа 0а все новые тексты — через словарь, не строкой в коде** (решение CEO, выход на мировой рынок).
- **Всё, что может стать дополнением** (OFFICE.md, этап 11), — отдельным модулем со своими таблицами в `src/data/` и правилами в `src/sim/`; игра без модуля работает, проходит тесты и открывает сохранения.
- Перед заметным изменением механики, которое меняет задумку, спроси владельца.

## Команды
- `npm test` — сборка и все тесты (Node 20+).
- `npm run build` — только сборка.
- `python3 tools/browser-smoke.py [chrome]` — необязательный стресс-тест в браузере (нужен playwright).
